title: Error codes
description: The JSON error envelope and the full table of error codes, HTTP statuses, and triggers.
---

Every non-2xx response from `/api/v1` is the same shape:

```json
{
  "error": {
    "code": "not_found",
    "message": "No message with that message-id.",
    "details": {}
  }
}
```

- **`code`** — a stable `snake_case` slug, decoupled from the HTTP status so you can branch on it
  without parsing `message` or overloading the status code. Codes are never renamed once shipped.
- **`message`** — human-readable, safe to display. Never leaks internals — no stack traces, no SQL.
- **`details`** — optional structured context (e.g. which parameter was invalid). Omitted entirely
  when there's nothing to add — never `null` or an empty object by force.

No Phoenix HTML error page ever leaks through on an `/api/v1` route; every failure, expected or
not, renders this envelope.

## Codes

| HTTP status | `code` | Trigger |
| --- | --- | --- |
| 400 | `invalid_cursor` | A `before`/`after` cursor value doesn't decode — hand-edited, truncated, or from a different endpoint. Cursors are opaque; don't construct or parse them. |
| 400 | `invalid_query` | `q` is missing or blank on `/search`. |
| 400 | `invalid_message_id` | The base64url `:b64id` path segment on a `/messages/...` route doesn't decode to a valid message-id. |
| 400 | `invalid_sha` | The `:sha` path segment on a `/commits/...` route isn't a 40-character hex string. |
| 401 | `unauthorized` | Missing or invalid API key. Every `/api/v1` route requires one — see [authentication](/concepts/authentication/). |
| 404 | `not_found` | No resource with that identifier — unknown message-id, list, sender, thread, commit, or attachment id. |
| 422 | `invalid_params` | The request parsed fine but isn't allowed — `limit` out of range, `before` and `after` both set, an unparseable date range. `details` names the offending field. |
| 500 | `internal_error` | Unexpected failure. Not your input — retry, and if it persists, that's a bug on our side. |

400 vs. 422 is the usual split: 400 means the input couldn't even be understood (a malformed
cursor, a missing search term, a path segment that isn't the shape it claims to be); 422 means it
was understood but isn't a valid combination.

New codes get added as new failure modes show up; existing codes are never renamed or repurposed.
