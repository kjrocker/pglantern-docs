`horton` is a `gh`-style command-line client for the pgLantern JSON API
(`/api/v1`). It's a deliberately thin wrapper: it validates required
arguments and flag types, passes everything else through verbatim, and
prints the server's error message when a request is rejected. Domain
validation — date formats, cursors, major names, bounds — stays on the
server, not duplicated in the client.

The project is called pgLantern; the binary stays `horton`.

Source: [codeberg.org/kehvyn/horton-cli](https://codeberg.org/kehvyn/horton-cli).

## Install

There's no published binary yet — build from source with
[mise](https://mise.jdx.dev) (or Go 1.24+ directly):

<Steps>

1. Clone the repo:

   ```bash
   git clone https://codeberg.org/kehvyn/horton-cli.git
   cd horton-cli
   ```

2. Install the pinned Go toolchain and build:

   ```bash
   mise install
   go build -o horton .
   ```

3. Put the resulting `horton` binary on your `$PATH`.

</Steps>

## Log in

API keys are minted in the web UI at
[app.pglantern.com/users/api-keys](https://app.pglantern.com/users/api-keys).

```bash
horton login --host https://app.pglantern.com
```

This prompts for the key, validates it against the server (a cheap
authenticated `GET /versions`), and saves both the key and host. For
scripting, skip the prompt:

```bash
horton login --host https://app.pglantern.com --with-token < key.txt
```

`horton logout` deletes the saved credentials.

## Config file and precedence

The host and key are stored in `~/.config/horton/config.json`, mode `0600`:

```json
{
  "host": "https://app.pglantern.com",
  "api_key": "hml_…"
}
```

Every command resolves host and key independently, highest priority first:

1. `--host` / `--api-key` flags
2. `$HORTON_HOST` / `$HORTON_API_KEY`
3. the config file

If nothing resolves a key, the command fails with a reminder to log in.
If nothing resolves a host, `horton` falls back to `http://localhost:4000`
— the Phoenix dev default — so **always run `horton login --host
https://app.pglantern.com` first**, or export `HORTON_HOST`, before pointing
it at the hosted API.

## Global flags

These apply to every command:

| Flag | Effect |
| --- | --- |
| `--json` | Print the raw response body instead of a table |
| `--host` | Override the resolved API host for this invocation |
| `--api-key` | Override the resolved API key for this invocation |

`--json` output is indented when writing to a terminal and compact
(jq-friendly) when piped:

```bash
horton messages --limit 3 --json | jq '.data[].subject'
```

Without `--json`, every command renders a human-readable table or detail
view built from the same response.

## The stderr cursor footer

List commands paginate with cursors (see [Pagination](/concepts/pagination/)).
Rather than mixing a cursor into the table and breaking anything piping
stdout, `horton` prints the next-page cursor to **stderr**:

```bash
$ horton messages --list pgsql-hackers --limit 10
SENT AT               FROM                  SUBJECT                          MESSAGE-ID
2024-03-11T14:22:03Z  alice@example.com     Re: VACUUM FULL and visibility…  MjAyNC0w...
…
# next: --after g3QAAAAC...
```

The `# next: --after …` line goes to stderr, so `horton messages … | jq
'.data'`-style pipelines never see it, and copy-pasting it as the next
command's flags just works. Commands without pagination (like `horton
lists` or `horton versions`) don't print a footer.

## The `api` escape hatch

For endpoints or query parameters this CLI doesn't wrap yet, `horton api`
sends a raw `GET` to any `/api/v1` path and prints the JSON response:

```bash
horton api /search --param q=vacuum --param limit=5
```

The path is relative to `/api/v1`; `--param key=value` is repeatable and
maps directly to query-string parameters. Authentication and host
resolution work exactly as with any other command.

## Message-Ids

Commands that take a Message-Id (`messages get`, `messages thread`,
`messages commits`, `messages refs`) accept the raw `Message-Id` exactly as
tables print it — a surrounding `<>` from a mail header is fine too. The
CLI base64url-encodes it into the URL path for you. A token already copied
out of an API URL works as-is. See [Message-Ids](/concepts/message-ids/)
for the encoding details.

## Shell completion

Completions are generated by Cobra:

```bash
horton completion zsh > ~/.local/share/zsh/site-functions/_horton
```

`bash`, `fish`, and `powershell` work the same way — run `horton completion
--help` for shell-specific setup notes.
