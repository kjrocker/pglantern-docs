pgLantern is a query layer over the Postgres mailing lists — `pgsql-hackers`,
`pgsql-general`, and the rest, as structured, queryable data. Everything below hits the same
API a script or CI job would use.

## Your first call — no key needed

Every `/api/v1` endpoint works without a key on the anonymous per-IP tier (20 API
credits/day, 5 requests/minute per IP — 20 lookups, or 4 searches).

Base URL: `https://pglantern.com/api/v1`.

```sh check=lists-anon
curl -s https://pglantern.com/api/v1/lists | jq -r '.data[].name'
```

```txt output=lists-anon

pgsql-advocacy

```

## Mint a key

A key raises the limits (free tier: 10,000 credits a **year** — 10,000 lookups, or 2,000
searches — at 60 requests/minute) and ties usage to your account instead of your IP.

The budget belongs to the **account**, mint as many keys as you need. `/users/api-keys`
shows the pool, which key is spending it, and when it refills.

The year runs from your own anniversary, and is visible via `x-ratelimit-reset` on every
response.

<Steps>

1. Sign up at [pglantern.com](https://pglantern.com).

2. Mint a key at [pglantern.com/users/api-keys](https://pglantern.com/users/api-keys). The
   raw key is only shown at creation, so put it somewhere safe.

</Steps>

Send it with either header (`Authorization` is checked first):

```
Authorization: Bearer hml_xxxxxxxxxxxxxxxxxxxxxxxxxxxx
X-API-Key: hml_xxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

Export it once and reuse it in the examples below:

```sh
export PGLANTERN_KEY=hml_xxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

## Two more curls

### Full-text search

```sh check=search-slots
curl -s -H "Authorization: Bearer $PGLANTERN_KEY" \
  "https://pglantern.com/api/v1/search?q=logical+replication+slot&list=pgsql-hackers&limit=2" \
  | jq '{total, next_cursor, data: [.data[] | {message_id, subject, sent_at, sender: .sender.display_name}]}'
```

The full envelope carries more per message — `from_raw`, `to_raw`, `cc_raw`, `sender.email`,
the list memberships, the archive URLs — projected out here; the
[API reference](/reference/api/) has the exhaustive shape.

Default order is relevance (capped at 200 results); `sort=sent_at` switches to the uncapped,
index-backed recency ordering. See the [search examples](/examples/search/) for the full
filter set (`list`, `from`/`to`, `sender`, `committed`, `path`, …).

### Fetch one sender

```sh check=sender-get
curl -s -H "Authorization: Bearer $PGLANTERN_KEY" \
  https://pglantern.com/api/v1/senders/48 | jq '.data | {id, display_name, stats}'
```

```json output=sender-get
{
  "id": 48,
  "display_name": "Tom Lane",
  "stats": {
    "first_message_at": "1998-04-15T20:25:36Z",
    "last_message_at": "2025-12-31T23:37:36Z",
```

A bad key gets a `401` in the standard error envelope; an unknown id gets a `404` in the
same shape.

## Install lantern

`lantern` is a `gh`-style CLI over this same API:

```sh skip=installs-from-the-network
curl -fsSL https://raw.githubusercontent.com/kjrocker/pglantern-cli/main/install.sh | bash
```

The installer downloads the release binary to `~/.local/bin` (override with `--bin-dir`).

Like the API, the CLI needs no key to work — keyless commands run on the same anonymous
per-IP tier:

```sh check=cli-lists
lantern lists
```

## Log in

To put your key behind every command, log in once:

```sh skip=interactive-prompt
lantern login --host https://pglantern.com
```

This prompts for the key you minted above, validates it against the server, then stores it —
with the host — in `~/.config/lantern/config.json` (mode `0600`). `lantern logout` deletes
the file. For scripts, pipe the key in instead: `lantern login --with-token < key.txt`. The
`LANTERN_HOST` / `LANTERN_API_KEY` environment variables override the config file when set.

Once logged in, host and key are implicit on every command — no more repeating headers and
URLs:

<Tabs>
<TabItem label="curl">

```sh check=lists-curl-tab
curl -s -H "Authorization: Bearer $PGLANTERN_KEY" \
  https://pglantern.com/api/v1/lists | jq -r '.data[].name'
```

</TabItem>
<TabItem label="lantern">

```sh check=lists-cli-tab
lantern lists
```

</TabItem>
</Tabs>

Every command renders a human-readable table by default; add `--json` for the raw response
body:

```sh check=cli-lists-json
lantern lists --json | jq -r '.data[].name' | head -5
```

```txt output=cli-lists-json
buildfarm-members
pgsql-admin
pgsql-advocacy
pgsql-announce
pgsql-bugs
```
