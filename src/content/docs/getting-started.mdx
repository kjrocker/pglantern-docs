pgLantern is a query layer over the Postgres mailing lists — `pgsql-hackers`, `pgsql-general`,
and the rest, as structured, queryable data. Everything below hits the same API a script or CI
job would use.

## Your first call — no key needed

Every `/api/v1` endpoint works without a key on the anonymous per-IP tier
(1,000 requests/day, 24/minute per IP). Base URL: `https://pglantern.com/api/v1`.

```sh check=lists-anon
curl -s https://pglantern.com/api/v1/lists | jq -r '.data[].name'
```

```txt output=lists-anon

pgsql-advocacy

pgsql-www
```

## Mint a key

A key raises the limits (free tier: 2,000 requests/day) and ties usage to your account instead
of your IP.

<Steps>

1. Sign up at [pglantern.com](https://pglantern.com).

2. Mint a key at [pglantern.com/users/api-keys](https://pglantern.com/users/api-keys).
   The raw key is shown once, at creation — copy it now.

</Steps>

Send it with either header (`Authorization` is checked first):

```
Authorization: Bearer hml_xxxxxxxxxxxxxxxxxxxxxxxxxxxx
X-API-Key: hml_xxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

Export it once and reuse it in the examples below:

```sh
export HORTON_API_KEY=hml_xxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

### Fetch one sender

```sh check=sender-get
curl -s -H "Authorization: Bearer $HORTON_API_KEY" \
  https://pglantern.com/api/v1/senders/48 | jq '.data | {id, display_name, email, stats}'
```

## Install lantern

`lantern` is a `gh`-style CLI over this same API:

```sh skip=installs-from-the-network
curl -fsSL https://codeberg.org/kehvyn/pglantern-cli/raw/branch/main/install.sh | bash
```

The installer downloads the release binary to `~/.local/bin` (override with `--bin-dir`). If
you already have Go 1.24+ configured, `go install codeberg.org/kehvyn/pglantern-cli@latest`
works too.

Like the API, the CLI needs no key to work — keyless commands run on the same anonymous
per-IP tier:

```sh check=cli-lists
lantern lists
```

## Log in

To put your key behind every command, log in once:

```sh skip=interactive-prompt
lantern login --host https://pglantern.com
```

This prompts for the key you minted above, validates it against the server, then stores it —
with the host — in `~/.config/lantern/config.json` (mode `0600`). `lantern logout` deletes the
file. For scripts, pipe the key in instead: `lantern login --with-token < key.txt`. The
`LANTERN_HOST` / `LANTERN_API_KEY` environment variables override the config file when set.

Once logged in, host and key are implicit on every command — no more repeating headers and
URLs:

<Tabs>
<TabItem label="curl">

```sh check=lists-curl-tab
curl -s -H "Authorization: Bearer $HORTON_API_KEY" \
  https://pglantern.com/api/v1/lists | jq -r '.data[].name'
```

</TabItem>
<TabItem label="lantern">

```sh check=lists-cli-tab
lantern lists
```

</TabItem>
</Tabs>

Every command renders a human-readable table by default; add `--json` for the raw response
body:

```sh check=cli-lists-json
lantern lists --json | jq -r '.data[].name' | head -5
```

```txt output=cli-lists-json
buildfarm-members
pgsql-admin
pgsql-advocacy
pgsql-announce
pgsql-bugs
```
