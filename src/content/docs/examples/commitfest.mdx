The [commitfest app](https://commitfest.postgresql.org/) tracks where a patch stands in
review: needs review, waiting on author, ready for committer, or one of its final outcomes.
pgLantern syncs it daily and joins it to the threads and commits it already links, so you
can ask what happened to a discussion without leaving the API.

All examples assume a key in `$PGLANTERN_KEY`. Outputs were captured against the archive as
of 2026-01-01. Commitfest state is as of 2026-11-04, limited to commitfests that started
before 2026; patches that later moved into a 2026 commitfest are left out of this snapshot.

## A thread's patches

`GET /messages/:message_id/commitfest` takes any message in a thread and returns the CF
patches attached to that thread, each with its current status and commitfest. This one is
the thread behind making `MultiXactOffset` 64-bit:

<Tabs>
<TabItem label="curl">

```sh check=thread-cf-curl
curl -s -H "Authorization: Bearer $PGLANTERN_KEY" \
  "https://pglantern.com/api/v1/messages/CACG%3DezaWg7_nt-8ey4aKv2w9LcuLthHknwCawmBgEeTnJrJTcw%40mail.gmail.com/commitfest" \
  | jq '.data[] | {id, name, authors, status: .current.status, cf: .current.cf_name}'
```

```json output=thread-cf-curl
{
  "id": 5205,
  "name": "Make MultiXactOffset 64-bit type",
  "authors": [
    "Maxim Orlov"
  ],
  "status": "needs_review",
  "cf": "PG19-3"
}
```

</TabItem>
<TabItem label="lantern">

```sh check=thread-cf-cli
lantern messages commitfest 'CACG=ezaWg7_nt-8ey4aKv2w9LcuLthHknwCawmBgEeTnJrJTcw@mail.gmail.com'
```

```txt output=thread-cf-cli
PATCH  STATUS        CF      NAME
5205   needs_review  PG19-3  Make MultiXactOffset 64-bit type
```

</TabItem>
</Tabs>

A thread can carry several patches — a reused thread where one patch was committed and a
follow-up opened on it — so `data` is a list. An empty list means the thread never entered a
commitfest.

## One patch: history, threads, commits

`GET /cf-patches/:id` is the cross-reference for one patch, keyed by its commitfest id (the
number in `commitfest.postgresql.org/patch/<id>/`). Dean Rasheed's `RETURNING OLD/NEW` patch
moved through five commitfests before it was committed in 2025-01:

```sh check=patch-history
curl -s -H "Authorization: Bearer $PGLANTERN_KEY" \
  "https://pglantern.com/api/v1/cf-patches/4723" \
  | jq -r '.data.history[] | [.cf_name, .status, .entered_at, .left_at] | @tsv'
```

```txt output=patch-history
2024-01	moved	2023-12-26T09:18:21Z	2024-02-01T18:08:28Z
2024-03	moved	2024-02-01T18:08:28Z	2024-04-09T06:23:08Z
2024-07	moved	2024-04-09T06:23:08Z	2024-08-01T06:14:31Z
2024-09	moved	2024-08-01T06:14:31Z	2024-10-08T03:33:38Z
2024-11	moved	2024-10-08T03:33:38Z	2024-12-03T12:19:29Z
2025-01	committed	2024-12-03T12:19:29Z	2025-01-16T15:23:01Z
```

`history` is every entry oldest first; `moved` means the patch moved on to the next
commitfest. `current` is the one entry that isn't `moved`. The same response carries the
threads the patch cites and the commits those threads landed:

```sh check=patch-links
curl -s -H "Authorization: Bearer $PGLANTERN_KEY" \
  "https://pglantern.com/api/v1/cf-patches/4723" \
  | jq '{threads: [.data.threads[] | {message_id, thread_id}],
         commits: [.data.commits[] | {sha, subject, sources}]}'
```

## A commitfest's entries

`GET /commitfests` lists the commitfests with their dates and per-status entry counts;
`GET /commitfests/:id/patches` lists one cf's entries. `status=` takes a status slug or
`open`/`closed`, and it filters on the entry's status **in that commitfest**. Each row also
carries `current`, which can sit in a later cf.

<Tabs>
<TabItem label="curl">

```sh check=cf-patches-curl
curl -s -H "Authorization: Bearer $PGLANTERN_KEY" \
  "https://pglantern.com/api/v1/commitfests/51/patches?status=ready_for_committer" \
  | jq -r '.data[] | [.id, .entry.status, .name] | @tsv'
```

```txt output=cf-patches-curl
4240	ready_for_committer	Cross-database SERIALIZABLE safe snapshots
5158	ready_for_committer	Blast-RADIUS mitigation
```

</TabItem>
<TabItem label="lantern">

```sh check=cf-patches-cli
lantern commitfests patches 51 --status ready_for_committer
```

```txt output=cf-patches-cli
PATCH  STATUS               NAME                                        AUTHORS
4240   ready_for_committer  Cross-database SERIALIZABLE safe snapshots  Thomas Munro
5158   ready_for_committer  Blast-RADIUS mitigation                     Thomas Munro
```

</TabItem>
</Tabs>

Commitfest 51 is `2025-01`. Find a cf's id with `lantern commitfests` or `GET /commitfests`.

## Filter search and threads by CF status

`cf_status=` on `/search` and `/threads` keeps threads attached to a patch whose **current**
status matches: a slug, `open` (needs review, waiting on author, ready for committer),
`closed`, or `any`. Combined with `path=`, it answers "which nbtree threads are waiting on
review?":

<Tabs>
<TabItem label="curl">

```sh check=cf-search-curl
curl -s -H "Authorization: Bearer $PGLANTERN_KEY" \
  "https://pglantern.com/api/v1/search?q=btree&path=src/backend/access/nbtree/&cf_status=needs_review&limit=5" \
  | jq -r '.data[] | [.sent_at, .sender.display_name, .subject] | @tsv'
```

## Limits

- **Current status only.** `cf_status=` and `current` reflect where a patch stands now. A
  patch's past statuses show up in `history`, but they don't match a filter.
- **`committed` is the commitfest app's claim.** The git history is authoritative for what
  landed. Check `GET /messages/:message_id/commits` or the `commits` on a patch.
- **A null `thread_id` is data, not an error.** The patch cites a message the archive
  doesn't hold, such as a thread on a list we don't ingest. Its `message_id` is still the
  commitfest app's value.
- **Ids are integers.** An unknown patch or commitfest id is a `404`; a non-integer one is a
  `422`:

```sh check=cf-errors
curl -s -H "Authorization: Bearer $PGLANTERN_KEY" "https://pglantern.com/api/v1/cf-patches/999999"
echo
curl -s -H "Authorization: Bearer $PGLANTERN_KEY" "https://pglantern.com/api/v1/cf-patches/abc" | jq -c .error.code
```

```txt output=cf-errors
{"error":{"code":"not_found","message":"No resource was found with that identifier."}}
"invalid_params"
```
