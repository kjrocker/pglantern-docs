pgLantern hosts an MCP server at `https://pglantern.com/mcp`. It exposes our endpoints as
tools so the agent doesn't need to work with `lantern` or the API directly. Every tool call
is a real `/api/v1` request, so the parameters and impact on account usage quotas are
identical.

An [API key](/getting-started/#mint-a-key) is required — send it as
`Authorization: Bearer hml_…` on the MCP connection; keyless requests get a `401`.

## Claude Code

```sh
claude mcp add --transport http pglantern https://pglantern.com/mcp \
  --header "Authorization: Bearer $PGLANTERN_KEY"
```

## claude.ai

**Settings → Connectors → Add custom connector**, URL `https://pglantern.com/mcp`, and add a
request header `authorization` with value `Bearer hml_…` (your key).

Request-header auth for custom connectors is a recent feature, if the header fields aren't
available on your account yet, use Claude Code or the Messages API instead.

## The tools

| Tool                 | What it returns                                                                               |
| -------------------- | --------------------------------------------------------------------------------------------- |
| `search_messages`    | Full-text search over the archives; message summaries, `limit` ≤ 50                           |
| `get_message`        | One message in full: body text, sender, lists, attachment metadata                            |
| `get_thread`         | The whole thread containing a message, flat, oldest first                                     |
| `list_threads`       | Rank threads by last activity, start, or message count — optionally on one list               |
| `get_thread_commits` | Commits that landed from a thread (via `Discussion:` trailers)                                |
| `get_commit`         | One postgres.git commit by SHA: message, files, first-shipped releases                        |
| `get_commit_thread`  | The discussion a commit's `Discussion:` trailer points at                                     |
| `list_mailing_lists` | The lists in the archive — fills the `list` parameter on `search_messages` and `list_threads` |
| `list_gucs`          | A major version's GUC catalog; `changed_since` diffs it against an older major                |

Parameters mirror the [REST API](/reference/api/) exactly — the tool schemas are derived
from the same OpenAPI spec.

## Limits and errors

- A missing or invalid key is a `401`, your MCP client will report the connection as failed.
- API errors come back as MCP tool errors: a rate-limited call reads
  `rate_limited (HTTP 429): burst rate limit exceeded; retry after 37s`. Agents recover from
  these on their own.
- Message and commit bodies over 64KB are truncated in tool results, marked with
  `body_text_truncated: true` and a hint. The [REST API](/reference/api/) serves untruncated
  bodies.

<Aside>
The server is stateless and tools-only — no resources, no prompts, no OAuth. If your
client asks about authentication, the answer is "a bearer API key".
</Aside>
