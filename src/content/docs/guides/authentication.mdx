## Without a key

The full API is available, with very small per-IP limits, for anonymous access. This is a
low-friction way to test the API before signing up, but the limits are intentionally small
and it's not recommended for any kind of sustained use.

| Anonymous limit | Value                      |
| --------------- | -------------------------- |
| Quota           | 80 API credits per UTC day |
| Burst           | 10 requests per minute     |

That is 80 lookups, 40 listings, or 16 searches a day, counted per client IP.

We treat invalid keys as a 401 rather than falling back to the anonymous tier.

## Mint a key

Register with your email (we won't send you anything you don't ask for), and go to the
[API Keys page](https://pglantern.com/users/api-keys) to make your key.

We only show the full key once, so put it somewhere safe. There are no limits on the number
of API keys you can have, every key draws from your account's quota, and I track how much
each key uses independantly so you can see where the usage is.

Keys are not permissioned, are read only, and all keys are equivalent. The ability to
modify/manage keys is intentionally not part of the API. As with all things, reach out if
you have a use case for this.

Recommended usage is one key per machine/purpose. For example: one key for your local
`lantern` installation and another key for your agent's MCP server.

## Send the key

Send the key via `Authorization: Bearer <key>` (or the `X-API-Key` header if that's easier).
If you're using the `lantern` CLI, a simple `lantern login` will prompt you to enter a key.

## Quota and limits

Your account quota is shared across all your API keys, and reset every year. There's no
rollover.

Each request attaches `x-request-cost`, `x-ratelimit-*`, and a few other headers to give you
an idea of your usage.

| Header                  | On                | Value                                   |
| ----------------------- | ----------------- | --------------------------------------- |
| `x-request-cost`        | every response    | Credits this route charges — 1, 2, or 5 |
| `x-ratelimit-limit`     | metered responses | Credits in your window                  |
| `x-ratelimit-remaining` | metered responses | Credits left in it                      |
| `x-ratelimit-reset`     | metered responses | Unix timestamp the window resets at     |
| `x-ratelimit-tier`      | every response    | `anon`, `free`, `paid`, or `service`    |
| `retry-after`           | `429` only        | Seconds until the window resets         |

`x-request-cost` is the route's price list, not a receipt: it is set on a `401`, `422` and
`429` too. Keys with no metered limit get no `x-ratelimit-*` headers rather than fictional
ones.

Quota is spent in credits, priced per route:

| Cost | Routes                                                                                                                                                                                                         |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | `lists`, `versions`, `versions/:major/gucs`, `versions/:major/docs`, `imports`, `messages/:id` (+ `/thread`, `/commits`, `/refs`), `senders/:id`, `commits/:sha` (+ `/thread`), `attachments/:id` (+ `/patch`) |
| 2    | `messages`, `senders`, `threads`, `commits`, `attachments`, `source/activity`                                                                                                                                  |
| 5    | `search`, `analytics/*`                                                                                                                                                                                        |

| Tier               | Credits   | Window | Burst (requests/min) | In searches |
| ------------------ | --------- | ------ | -------------------- | ----------- |
| Anonymous (per IP) | 80        | day    | 10                   | 16          |
| Free               | 10,000    | year   | 60                   | 2,000       |
| Individual         | 50,000    | year   | 180                  | 10,000      |
| Team               | 1,000,000 | year   | 180                  | 200,000     |
| Commercial         | 1,000,000 | year   | 180                  | 200,000     |

Every keyed tier is annual; the anonymous tier is the exception and resets at UTC midnight.
Everything counts at its route's weight — cache hits, `304`s and `4xx`s included. A `429` is
the only response that doesn't count.

If you run out of your quota early, please reach out to me. I always want examples of heavy
use patterns.

## Revoking a key

Keys can be revoked from the UI. Revoking deletes the key, so a revoked key is
indistinguishable from one that never existed — and there is no caching in the lookup, so it
stops working on the very next request.

| Case                               | Status | `code`              |
| ---------------------------------- | ------ | ------------------- |
| Revoked, unknown, or malformed key | 401    | `unauthorized`      |
| Key past its expiry date           | 401    | `unauthorized`      |
| No key at all                      | 200    | anonymous tier      |
| Suspended account                  | 403    | `account_suspended` |
| Over quota or burst                | 429    | `rate_limited`      |

Credits a revoked key already spent stay on the account's pool for the year — revoking and
minting again is not a quota reset.
